# Работа с проектом в Codex

Целевая среда — приложение Codex с локальной папкой `snmp2mqtt`.
Процесс intent → spec → plan, решения человека и номера шагов сохранены из исходной карты для Claude Code.
Адаптация рабочего окружения выполнена в рамках шага 00; следующие этапы она не закрывает.

## Начало нового чата

1. Открой этот проект в Codex и создай чат для одного шага.
2. Возьми стартовый промпт нужного шага из `sdlc-roadmap.md`. Назови шаг явно.
3. Codex читает `AGENTS.md` и дорожную карту; нужные артефакты и референсы читает по задаче.
4. Все изменения оформляются в отдельной ветке через PR. Человек проверяет результат,
   подтверждает принятие артефакта и слияние. Коммит фиксирует принятое решение;
   коммит сам по себе не меняет `status: draft` на `accepted`.

Инициатива хранится в `intent/YYYY-MM-DD-<slug>/`, где дата — день создания intent по Москве.
Шаблоны находятся в `intent/_templates/`; правила имён, дат и переходов — в `intent/README.md`.
При переходе к spec или plan используется та же папка инициативы, даже если работа продолжается в другой день.

Следующий этап по таблице статусов — **01 PLAN**. Стартовый промпт:

```text
Прочитай AGENTS.md и docs/sdlc-roadmap.md. Мы на шаге 01 PLAN.
Я расскажу идею проекта своими словами. Задавай уточняющие вопросы (не больше 3 за раз),
пока не заполнишь все разделы intent/_templates/intent.md. Не придумывай требования за меня:
чего я не сказал — записывай в «Открытые вопросы». Результат положи в intent/YYYY-MM-DD-<slug>/intent.md
со status: draft. Подготовь изменения к PR; принятие intent и слияние подтвержу я.
```

## Соответствие файлов

| В исходном процессе Claude Code | В процессе Codex | Когда вводится |
|---|---|---|
| `CLAUDE.md` с правилами | `AGENTS.md`; отдельный `CLAUDE.md` удалён | 00 |
| `.claude/skills/<name>/SKILL.md` | `.agents/skills/<name>/SKILL.md` | 02a |
| `.claude/settings.json` | `.codex/config.toml`; синтаксис настроек проверяется отдельно | 03a |
| hooks в `.claude/settings.json` | `.codex/hooks.json` и скрипты `.codex/hooks/` | 03a–05 |
| `.claude/agents/*.md` | `.codex/agents/*.toml` для ролей, если нужны постоянные настройки | 04 |
| `claude --worktree …` | Worktree в приложении Codex; путь согласуется до создания | 03b |
| `claude -p` | `codex exec` с явно выбранными ограничениями | 06 |

Это соответствие назначения файлов. Содержимое конфигураций требует отдельной настройки,
а не замены названий каталогов. Сейчас `.agents/skills/`, `.codex/hooks/` и `.codex/agents/`
содержат только заготовки `.gitkeep`; Go-модуля, навыков, конфигов и действующих hooks ещё нет.

## Ограничения и проверка

`AGENTS.md` и skills задают поведение агента. Технический контроль доступа обеспечивается
средой выполнения и её политиками. Перед выходом из проекта, сетевым запросом или подключением
сервиса нужно разрешение пользователя на конкретный путь или адрес. Worktree вне проекта
также требует согласования. Разрешения одного чата не действуют в следующем.

Hooks Codex требуют доверия к проекту и проверки самой конфигурации hook. На шаге 03a
нужно проверить их срабатывание в установленном приложении. Hooks охватывают не все инструменты;
запрет сети для shell сам по себе не закрывает поиск в интернете, приложения и MCP.
Критичные гейты дополнительно проверяются в CI и системе деплоя на шагах 04–05.

На шаге 03b сначала обсуждается и сохраняется план. Функциональная реализация начинается после
принятия и коммита `plan.md`. Название режима интерфейса не заменяет этот гейт.
Минимальный каркас Go вводится отдельным шагом 03a.

В отчётах различаем `[ПРОВЕРЕНО]`, `[ВЫВОД]` и `[ДОГАДКА]`. Проверка документации
не подтверждает, что hooks, роли или автоматизации уже запущены в этом проекте.
